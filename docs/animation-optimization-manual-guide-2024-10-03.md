# PixelFlow 动画优化实施说明

更新时间：2026-10-03

本文记录 apps/desktop/src/styles.css 和 apps/desktop/src/App.vue 的实际实现，不包含待粘贴的代码。

## 当前实现

- 按钮、选项卡和设置图标提供短暂的按压反馈；输入框聚焦时过渡边框和阴影。
- 进度条宽度使用 0.4 秒 ease-out 过渡；真实进度仍限制在 0–1000。完成后保留 700ms 的视觉状态，填充条做约 3% 的短暂回弹并恢复到 100%。
- 确认列表卡片由 Intersection Observer 按进入滚动区域显示；前 20 张按索引错开动画，后续卡片进入视口后使用同一淡入动画。所有卡片仍由 Vue 一次渲染。
- 设置、确认页和结果报告使用面板独立的缩放/位移动画，背景遮罩单独淡入并过渡模糊，不缩放整个遮罩层。
- 确认网格底部提示使用绝对定位渐变覆盖层，不参与网格排版；无溢出或滚到底部时隐藏。
- 预览仍由既有视口观察器排队读取。等待请求时显示“预览加载中…”，读取期间显示骨架；普通模式下骨架有动画，减少动态效果时为静态。图片加载完成后淡入，读取失败时显示“预览不可用”。
- 未请求、读取中和读取失败时都有文字或骨架占位，不会留下空白预览框。

## 减少动态效果

“通用设置 → 关闭动画”通过 .reduce-motion 关闭动画和过渡。系统 prefers-reduced-motion 也会关闭动画和过渡，并取消新增的按钮/选项卡位移反馈。

## 验证边界

本轮代码检查覆盖 CSS 构建、卡片观察器降级、前 20 张延迟、后续卡片视口淡入、滚动遮罩排版以及手动和系统减少动态选择器。未在 Tauri 窗口中做逐项人工动效检查，也未测量 300 张素材时的帧率或卡顿情况；这些表现不作为已验收结论。
