# PixelFlow v3 图像引擎适配需求

## 一、总目标

在保留 v2.6 已验证输出行为的基础上，把图像处理能力逐步迁移到 v3 Worker，最终解除 v3 对 `PixelFlow-App-v2.0` 目录的运行时依赖。

本项目采用渐进式适配，不从零重写全部图像算法。v2.6 适配器在 v3 新核心完成回归前持续保留。

迁移优先级为：先抽取构图计划层，再迁移鞋类构图，之后迁移其他品类，最后迁移渲染和输出层。

## 二、阶段 0：冻结当前行为

### 工作内容

- 记录 v2.6 当前输出行为：
  - 产品主图；
  - 模特图；
  - 含 Logo / 无 Logo；
  - 唯品图；
  - 透明图；
  - 输出目录；
  - 1440x1440、1440x1920、1125x1500 三种尺寸。
- 固化现有测试素材和输出基线。
- 明确必须保持兼容的结果。

### 验收标准

- 同一批输入在迁移前后数量、尺寸和路由一致。
- 旧版输出作为回归基准保存。
- 基线至少包含产品主图、模特图、Logo / 无 Logo、唯品图和透明图。

## 三、迁移期间的运行模式

迁移期间 Worker 支持以下模式：

- `legacy`：使用现有 v2.6 适配器；
- `v3`：使用已迁移的 v3 图像核心；
- `compare`：同时计算两套构图计划并记录差异，正式输出仍以兼容路径为准。

`compare` 模式用于定位差异，不覆盖正式输出，也不改变用户已有的输出目录。

## 四、阶段 1：建立 v3 图像核心接口

### 工作内容

在 `worker/pixelflow_core` 中定义明确的数据结构：

- `ClassificationResult`
- `CompositionPlan`
- `ProtectedRegion`
- `RenderRequest`
- `RenderResult`

将当前依赖动态字典的字段整理成稳定接口。

### 验收标准

- v3 Worker 可以通过明确请求调用图像核心。
- v3 不需要直接操作 v2 模块内部变量。
- 旧适配器仍可以继续工作。

## 五、阶段 2：抽取构图层

### 工作内容

迁移以下能力：

- 品类目标区域；
- 人物位置；
- Pose 关键点；
- Seg 证据；
- 保护区域；
- 方图和竖图比例；
- 正常姿态与高风险姿态判断；
- 保守构图回退。

优先迁移鞋类：

- 脚踝和脚部定位；
- 鞋面、鞋尖、鞋底保护；
- 动作幅度判断；
- 脚部遮挡判断；
- 人物框贴边判断；
- 高风险素材人工复核提示。

### 验收标准

- 正常鞋图保持鞋部完整。
- 大幅动作鞋图不继续激进放大。
- 高风险素材生成明确的复核提示。
- 双人、多人鞋图不凭空补全被遮挡脚部。

### 鞋类测试矩阵

鞋类迁移必须覆盖以下素材类型：

- 正常站姿；
- 大幅弯腿；
- 单脚；
- 交叉腿；
- 脚部遮挡；
- 鞋底朝向镜头；
- 人物框贴边；
- 双人和多人。

每张测试图至少记录：分类结果、Pose / Seg 证据、保护框、裁剪比例、风险标记、人工复核标记和最终输出。

## 六、阶段 3：复用并抽取渲染层

### 工作内容

保留现有成熟逻辑，并迁移为 v3 Renderer：

- PIL 等比例缩放；
- 安全裁剪；
- 背景延展；
- Logo 叠加；
- JPG 输出；
- 透明图输出；
- 唯品图输出；
- 文件大小限制；
- 输出校验。

### 验收标准

- 不发生非等比例拉伸。
- 输出尺寸和色彩模式符合要求。
- Logo、透明图和唯品图结果保持兼容。
- 输出目录结构不变。

## 七、阶段 4：迁移缓存和模型接口

### 工作内容

- 将 Pose / Seg 缓存接口纳入 v3 Worker。
- 保留缓存版本控制。
- 构图算法变更时自动失效旧缓存。
- 缓存键包含源文件版本、Pose 模型版本、Seg 模型版本、构图规则版本、品类和输出尺寸。
- 统一外部 Pose / Seg 模型状态。
- 模型不可用时回退规则模式。

Seg 的职责需要明确：当前只能提供人物或主体轮廓证据时，Seg 只参与风险判断；只有具备可靠鞋部轮廓时，才允许直接参与鞋面、鞋尖和鞋底保护框计算。

### 验收标准

- 旧构图参数不会污染新结果。
- 模型缺失不会导致任务崩溃。
- Worker 能明确报告模型不可用和回退状态。

## 八、阶段 5：切换 v3 默认路径

### 工作内容

- v3 默认调用新的图像核心。
- v2.6 适配器保留为兼容和回退路径。
- 对比新旧输出并修复差异。
- 最后移除 v3 对 v2 文件路径的直接依赖。

### 验收标准

- v3 Worker 不再动态导入 `PixelFlow-App-v2.0`。
- v3 可以独立打包和运行。
- v2.6 目录不可用时，v3 仍能正常生成。

## 九、量化兼容标准

- 输出数量一致。
- 输出尺寸一致。
- 输出目录和命名规则一致。
- 产品类素材在无构图算法变化时保持像素级一致，或记录明确的允许差异。
- 模特图目标区域不能被裁掉。
- 所有图像处理必须保持等比例缩放，不允许非等比例拉伸。
- Logo、透明图、唯品图和文件大小限制通过独立回归。

## 十、明确不做的事情

- 不从零重写全部图像算法。
- 不立即删除 v2.6 引擎。
- 不改变已有输出目录规范。
- 不引入新的图像生成模型。
- 不为了架构重构修改无关 UI。
- 不在没有回归基线的情况下直接删除 v2.6 适配器。

## 十一、最终完成标准

1. v3 拥有独立的分类、构图和渲染接口。
2. 鞋类复杂动作图具备保守回退能力。
3. 鞋类测试矩阵全部通过，异常样本可以进入人工复核。
4. v2.6 输出行为通过回归测试。
5. `legacy`、`v3` 和 `compare` 模式行为明确且可复现。
6. v3 可独立打包 macOS `.app`。
7. v3 不再依赖 `PixelFlow-App-v2.0` 的运行时路径。
8. 旧 v2.6 适配器在迁移完成前持续作为兼容和回退方案。
